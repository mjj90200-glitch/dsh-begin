# 美术资源契约

启动页的观感上限由**素材分层**决定，不由代码决定。这份文档写清楚要什么、
为什么、以及拿不到时怎么降级。

## 为什么必须分层

单张平面立绘能做的只有「整体轻微缩放 / 位移」（呼吸）。而「她被你在看着」这件事
需要**零件级**的控制：

| 效果 | 需要哪一层 | 单张 PNG |
|---|---|---|
| 呼吸（起伏、轻微摇摆） | 整图 | ✅ 勉强 |
| 入场（淡入 / 滑入） | 整图 | ✅ |
| **眨眼** | 眼白 + 眼睑（或闭眼帧） | ❌ |
| **视线跟随鼠标** | 虹膜 / 瞳孔独立层 | ❌ |
| **说话口型** | 嘴部 3–4 帧 | ❌ |
| 歪头 | 头颈分离 | ❌ |
| 发丝飘动 | 头发前 / 后分层 | ❌ |

「人性」的入口是**眼睛**。动画师在 Chloe 身上最后的手工活儿也全在眼睛上。

## 分层清单

> 所有图层必须**同一画布尺寸、同坐标**导出，透明背景，不要裁切到内容边界。
> 建议画布 1200 × 1600 或 2048 × 2732（2x）。

### 必需（做到「呼吸 + 眨眼」）

| 图层 | 文件名 | 说明 |
|---|---|---|
| 身体（含裙子、尾巴、手臂） | `body.png` | 除头部以外的一切 |
| 后发 | `hair-back.png` | 压在身体之后的长发 |
| 头部（脸 + 五官底） | `face.png` | 不含虹膜、眼睑、嘴 |
| 眼白（左右可合并） | `eye-sclera.png` | |
| 虹膜 + 瞳孔 | `eye-iris.png` | **左右分开更好**：`eye-iris-l.png` / `-r.png` |
| 闭眼（含睫毛） | `eye-closed.png` | 眨眼时整层替换；半闭可从闭眼层做 50% 位移 |
| 前发（刘海） | `hair-front.png` | |

### 加做「视线跟随」（强烈建议）

在必需项基础上，虹膜层需要**比眼白小一圈**（这样才能在眼眶里位移），
并额外提供：

| 图层 | 文件名 | 说明 |
|---|---|---|
| 上眼睑 | `lid-upper.png` | 用于半闭、困倦、向下看 |

### 加做「说话口型」（可选）

| 图层 | 文件名 | 说明 |
|---|---|---|
| 嘴 · 闭 | `mouth-0.png` | |
| 嘴 · 微开 | `mouth-1.png` | |
| 嘴 · 开 | `mouth-2.png` | |
| 嘴 · 圆（お/う 音） | `mouth-3.png` | |

## 交付格式

任选其一：

1. **PSD 分层文件**（最好）—— 保留图层名与对齐，可逆
2. **PNG 分层文件夹** —— 按上表命名，同一画布尺寸
3. **序列帧**（只适合口型 / 眨眼）—— `blink-0.png` … `blink-2.png`

不接受：已经拍平的单张 JPG/PNG（除了作为临时占位）。
不接受：带白底的图（抠图边缘在深色启动页上会发光）。

## 拿不到分层时的三个降级方案

### 方案 A —— 整图微动（零成本，最快）

单张立绘 + 呼吸缩放 + 4.6 秒周期的轻微摇摆 + 入场淡入。
**代价**：没有眨眼、没有视线跟随。她会像个精致的手办，而不是一个在等你的存在。

### 方案 B —— 表情包插播（中等成本）

社区有 [161 个 GIF 表情](https://github.com/BrickAZ/deepseek-chan-emotes) 与
[档案馆](https://github.com/EDMOK/blue-fish-archive)。可以在「说某句话」时插入一张
对应表情，播完切回主立绘。
**代价**：切换是硬切，风格可能与主立绘不统一；且表情素材另有授权，需逐张确认。

### 方案 C —— 伪 Live2D（我这边可做）

用**分层 PNG + canvas/CSS 变换**自己实现一套轻量骨骼与表情驱动：
呼吸位移、眨眼定时器、虹膜跟随鼠标、口型帧切换。

**这不是 Live2D 模型**——`.moc3` 是 Cubism 的私有格式，必须用 Cubism Editor 手工绑定，
我无法生成。但对着一个只停留几秒的启动页，方案 C 能拿到 80–90% 的观感，
而且**零运行时依赖**（不加载 Live2D SDK，不增加启动负担）。

如果确实要真 Live2D，需要：

1. 用 Cubism Editor 把分层图绑定成 `.model3.json` + `.moc3`（人工数小时）；
2. 运行时引入 `pixi-live2d-display` 之类 SDK —— 这会让启动页多几百 KB，
   与「启动页要快」直接冲突。
